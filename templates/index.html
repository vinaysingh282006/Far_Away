What is
Guardian Mesh?

Guardian Mesh is a low-cost, open-source environmental intelligence system built on ESP32 microcontrollers. It creates a self-organizing, multi-hop wireless sensor network that collects real-time environmental data from remote or disaster-prone areas — without requiring any internet connectivity or centralized infrastructure.

Each node in the mesh is an autonomous sensor station. When one node fails or loses power, surrounding nodes reroute data automatically. The system is designed to remain operational in the conditions where traditional communication fails: wildfires, floods, earthquakes, and remote terrain.

This dashboard is the ground-station control center: a real-time view into the mesh, enriched with external API context and powered by Gemini AI for automated incident analysis.

🕸️
Self-Healing Mesh
Nodes relay data via ESP-NOW. When a path fails, the mesh reroutes automatically with under 800ms failover latency.
🔬
Multi-Sensor Nodes
Temperature, humidity, pressure, AQI, rainfall, wind, light, battery — 8+ parameters per node, sampled every 5–30 seconds.
🌐
Web Context Fusion
Local readings are cross-referenced with Open-Meteo, AQICN, and NASA FIRMS satellite data for richer situational awareness.
🧠
AI Incident Analysis
Gemini AI synthesizes multi-node sensor anomalies into structured incident reports with severity, cause, and recommended actions.
📡
Zero Infrastructure
The network operates with no WiFi, no cellular, no satellite. It requires only ESP32 hardware and a solar-charged battery per node.
⚡
Edge Computing
Data processing happens at the gateway node. No cloud dependency required for local alerting and relay decision-making.
ARCHITECTURE

How the Mesh
Network Works

Every ESP32 node wakes on a configurable interval (default: 30 seconds), reads all onboard sensors, constructs a JSON telemetry packet, and broadcasts it over ESP-NOW — a lightweight, connectionless wireless protocol developed by Espressif.

Relay nodes receive packets from field nodes and forward them upstream, hop by hop, until the data reaches the Ground Station Gateway. The gateway is the only node connected to the internet. It receives all mesh traffic and pushes it to this dashboard via WebSocket.

If a relay node goes offline, surrounding nodes immediately attempt alternate paths. This is transparent to the operator — data continues flowing, possibly with a brief increase in latency.

📶
Protocol: ESP-NOW
2.4GHz direct peer-to-peer, no WiFi association needed
🔁
Routing: Store-and-Forward
Packets cached locally if relay is temporarily unavailable
⏱️
Latency: <800ms per hop
End-to-end latency across 5 hops typically under 4 seconds
