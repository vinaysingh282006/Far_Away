System Architecture

How Guardian Mesh Works

From a sensor node in a remote forest to an AI-generated incident report in under 5 seconds.

01
🌡️
Sensor Layer
ESP32 Sensor Nodes
Low-power ESP32 microcontrollers with DHT22, BMP280, MQ-135, rain and wind sensors. Each node samples every 5–30 seconds and transmits via ESP-NOW.
Temperature Humidity Pressure AQI Rainfall Wind
↓
02
📡
Relay Layer
ESP-NOW Multi-Hop Mesh
Relay nodes forward packets hop-by-hop. If Node A cannot reach the gateway, it routes through Node B → C. The mesh self-heals when nodes go offline.
NODE_A → NODE_B → GATEWAY (3 hops · ~680ms)
↓
03
🛰️
Gateway Layer
WiFi Gateway & FastAPI Server
The gateway ESP32 bridges the mesh to WiFi, POSTing telemetry to the FastAPI backend. The server writes to SQLite and broadcasts live via WebSocket.
↓
04
📊
Dashboard Layer
This Control Station
The web dashboard renders live sensor charts, shows mesh topology, detects anomalies, and surfaces AI-generated incident intelligence in real time.
↓
05
🤖
Intelligence Layer
AI Incident Analysis
When anomalies are detected, Gemini AI (primary) or Claude (secondary) generates a structured incident report — severity, cause, recommended action, and confidence score.
